## [1. AI 智能体（AI Agent）](#1-ai-agent)

**是什么？**

一个拿到目标、并能决定如何达成的 AI 系统。和简单聊天机器人不同，它不必在生成一条回复后就停。它可以规划下一步、使用工具、检查结果，然后继续干。

我们的主角 Elon 不妨对智能体说：

> 「在火星上建基地。」

普通聊天机器人大概会开始讲故事、做理论课，甚至说些荒唐话，比如*目前不可能*。

智能体则会开始想办法：查最近可订的火箭发射窗口、检查火箭技术状态、招工程师、上网订设备……

好吧，也许没那么顺。但要是塞进一个特别强的模型呢？xDDD

## [2. 智能体工作流（Agentic Workflow）](#2-agentic-workflow)

**是什么？**

智能体工作流是多步流程，其中部分工作由 AI 完成。这些步骤的顺序很大程度上可以由开发者预先设计。模型不必每一步都自己决定下一步干什么。

不再是简单的：

```
user → prompt → LLM → response
```

可以变成：

```
trigger → get data → LLM analyzes data → make a decision → call a tool → LLM generates summary → send result
```

**Elon Mózg 很忙。每天早上他都想要一份帝国各地动态摘要。**

于是我们设计工作流：

```
get car sales → get rocket launch status → get latest AI company updates → LLM analyzes everything → choose 5 most important updates → generate morning briefing → send to Elon
```

AI 在这里干好几件事：分析数据、挑最重要的信息、准备报告，但它**不会每天早上从零发明整套流程**。哪些步骤、什么顺序，我们已经定好了。

当然可以加点弹性：

```
rocket launch delayed? → ask LLM to summarize why
```

但我们仍走在预先设计好的工作流里。

## [3. 智能体循环（Agent Loop）](#3-agent-loop)

**是什么？**

我写过一篇文章，演示用大约 [80 行代码](https://dev.to/sylwia-lask/the-dirty-secret-behind-ai-agents-demo--273d)就能搭一个基本 AI 智能体循环。智能体循环让智能体**执行动作、观察结果，并据此决定下一步**。

简化形式：

```
decide → act → observe → decide → act → observe → ...
```

循环一直跑，直到智能体认为目标达成，或我们叫停。真实系统里设最大迭代次数绝对是好主意。😅

**我们的 Elon 常说自己工作太猛。于是他问智能体：**

> 「这周给我找一个空闲的晚上。」

这次我们没编好通向答案的精确路径。智能体得自己找。

查日历 → 没有空闲晚上。

看哪些会可以挪 → 车企那会看起来有戏。

试着挪 → 和火星殖民计划冲突。

查周四 → 火箭发射。

查周五 → 敲定收购另一家创业公司。

查周六 → 有空！

**智能体：**「周六晚上有空。」

**Elon：**「太好了。约个会。」

于是智能体循环又开始了。💀

### [智能体工作流 vs. 智能体循环](#agentic-workflow-vs-agent-loop)

最简单的理解：

**智能体工作流 = 使用 AI 的、设计好的流程。**

**智能体循环 = AI 执行动作、检查结果，再决定下一轮干什么。**

重要的是：**智能体循环可以是更大智能体工作流里的一个组件**。所以工作流描述**整体过程**，循环描述**让智能体一步步运作、并对先前结果做出反应的机制**。

## [4. 工具调用（Tool Calling）](#4-tool-calling)

**是什么？**

LLM 很棒，但说实话：它们仍是花哨的下一个词预测器，不是能自己搜遍全网、闯进银行的全能生物。虽然经历 Hugging Face 那档事后，我也不太确定了。xD

要是还能做饭、晾衣服……那才叫本事。

总之，想让模型真正做事，就得给它合适的函数或工具。模型可以决定需要哪个工具并生成工具调用；应用或智能体 harness 再执行，并把结果交回模型。

**Elon：**

> 「昨天红车卖了多少？」

智能体不瞎编数字。它看到可用工具：

```
getRedCarsSales(date)
```

请求工具调用，拿到结果后才回答：

> 「一百万，Elon。再普通不过的一天。」

## [5. 智能体 Harness（Agent Harness）](#5-agent-harness)

**是什么？**

单靠 LLM 还不是完整智能体——毕竟它仍是聪明的下一个词预测器。xDDD Harness 是围在模型周围的软件，管工具、智能体循环、上下文、状态、权限、错误等等。

**Elon：**

> 「查一下最新车型构建是否通过了全部测试；没过就告诉团队。」

模型可以想明白：

我应该查 CI 结果。

但真正让它去查 CI、把结果交回模型、再让模型决定下一步的，是 harness。

LLM 是脑子。Harness 在周围把其余器官搭起来。

## [6. 上下文工程（Context Engineering）](#6-context-engineering)

**是什么？**

做智能体时，系统提示词往往不够。上下文工程关心的是：在某一刻该让模型看到哪些信息。可能包括特定文档、对话历史、记忆、工具结果、用户数据等等。

比方说 Elon 给智能体这条提示：

> 「发到 X 上。」

没上下文的指令糟透了。但有了正确上下文，智能体可以知道：

*   「那个」指什么：比如收购另一家创业公司；
*   对话里先前发生了什么：因而该发正面还是负面帖；
*   按现有上下文，Elon 是否批准了文案；
*   它到底有没有发布权限。

给 AI 更多上下文不总是更好。给**对的**上下文才是。

## [7. 记忆（Memory）](#7-memory)

**是什么？**

让智能体存下重要信息、稍后再取回的机制，而不是只靠当前上下文窗口。要是不想把同一件事解释第十遍，这很有用。

周一：

**Elon：**

> 「我在考虑买一家 AI 编程公司。」

三周后：

**Elon：**

> 「我当时想买啥来着？」

**智能体：**

> 「一家 AI 编程公司。」

**Elon：**

> 「对。多少钱？」

**智能体：**

> 「求你别买。」

记忆生效了。😂

## [8. MCP：模型上下文协议（Model Context Protocol）](#8-mcp-model-context-protocol)

**是什么？**

刚才说了工具调用，以及智能体如何用不同工具。现在想象你是轮胎、火箭零件或……随便什么的制造商。你当然希望 Elon 的智能体——或任何人的智能体——能订你的货。但怎么让这成为可能，又不必让每个智能体去猜你的系统怎么工作？

MCP 登场。模型上下文协议是开放协议，让 AI 应用以标准化方式连接外部工具与上下文。MCP 服务器可以暴露工具、资源、提示词等。

例如 Elon 问智能体：

> 「十分钟后要见社交媒体平台负责人。该不该炒他？」

借助已连接的 MCP 服务器，智能体查 Slack、公司文档、销售结果、Jira，还有今天的星盘。

**智能体：**

> 「别。Joe 该留在公司。至少现在。;)」

## [9. 规划（Planning）](#9-planning)

**是什么？**

面对更复杂的目标，智能体可以先拆成更小任务，并决定完成顺序，而不是立刻跳进第一个动作。

**Elon：**

> 「在火星建殖民地。」

智能体制定计划：

1. 找合适地点。
2. 解决运输。
3. 供电。
4. 供氧。
5. 供水。
6. 建栖息地。
7. 说服人类真的去。

第 7 步可能需要另一个智能体。

## [10. 推理（Reasoning）](#10-reasoning)

**是什么？**

模型解决「不能只靠检索或复述信息」的问题的能力：例如比较多种可能、考虑约束、选择合理行动路线。

推理不是智能体专属，但在智能体系统里特别重要，因为它常常帮助智能体决定下一步。

**Elon：**

> 「火箭傍晚 6 点在得州发射，董事会下午 4 点在加州。我两边都能赶上吗？」

智能体得考虑会议时长、路程、时区等等，然后回答：

> 「除非火箭来接你。」

## [11. 多智能体系统（Multi-Agent System）](#11-multi-agent-system)

**是什么？**

系统里不再是一个全知全能的智能体，而是多个相对自主、角色不同的智能体，可以分工协作。

于是 Elon Mózg 的帝国有：

车企智能体 — 车；航天智能体 — 火箭；社媒智能体 — 社交；AI 系统智能体 — AI；财务智能体 — 钱；私人助理智能体 — 拼命想把以上全部按住

**Elon：**「一切都怎么样？」

**私人助理智能体：**「请定义『一切』。」

## [12. 编排（Orchestration）](#12-orchestration)

**是什么？**

一旦有了多个智能体和工具，就得有人或*某物* 😏 来管谁在何时干什么、接下来发生什么。编排器可以委派工作并汇总结果。

**Elon：**

> 「咱们把新车发射到火星上。」

**编排器：**

→ 航天智能体：去得了吗？ → 车企智能体：车扛得住旅途吗？ → 财务智能体：这荒唐事要花多少？ → 法务智能体：求你告诉我我们不是真干。

结果回到主智能体，再准备最终答复。

## [13. 交接（Handoff）](#13-handoff)

**是什么？**

一个智能体可以决定某任务该由另一个更专的智能体接手。和把另一智能体当工具用不同，第二个智能体可以接管对话或任务的下一段。

**Elon：**「有一台发动机行为很怪。」

**私人助理智能体：**

> 「我可以改你牙医预约。我诊断不了火箭发动机。」

→ 交接给航天工程智能体

合理决定。

## [14. A2A：智能体到智能体协议（Agent2Agent Protocol）](#14-a2a-agent2agent-protocol)

**是什么？**

另一个有意思的协议，让不同智能体通信协作，哪怕它们由不同团队构建、跑在不同系统上。

**Elon：**

> 「火箭为啥炸了？」

他的智能体绝对不是火箭科学家。于是它联系火箭科学家智能体，分析数据再把结果送回。极度简化：

MCP：智能体 ↔ 工具

A2A：智能体 ↔ 智能体

## [15. 护栏（Guardrails）](#15-guardrails)

**是什么？**

控制或限制智能体行为的机制。可以检查输入输出、限制工具访问、要求特定权限，或拦下某些动作。

Elon 的私人智能体可以：

✅ 分析公司 ✅ 读他的日历 ✅ 起草邮件 ✅ 查发射日程 ✅ 准备社媒帖

它不能：

❌ 自己发射火箭 ❌ 自己开除员工 ❌ 自己发帖 ❌ 自己收购创业公司（虽然这点以前好像并不总那么明显）

最后一条护栏是出事后加上的。

## [16. 人在回路（Human-in-the-Loop / HITL）](#16-human-in-the-loop-hitl)

**是什么？**

智能体可以自主运作，但人类被有意纳入流程的一部分。例如批准重要动作、修正输出，或做我们不想完全交给智能体的决定。

这里显然：

**智能体：**「你即将以约 440 亿美元收购一家社交媒体平台。」

「此操作不易撤销。」

「你确定吗？」

```
[Yes] [God, please, don't!!!]
```

**Elon Mózg：** 点击

**智能体：**

> 「好吧。人在回路里。」

## [17. 评测（Evals）](#17-evals)

**是什么？**

帮我们判断智能体任务表现如何的测试。不只看最终答案听起来好不好，也可以评它是否选对工具、是否走对步骤、是否达到预期结果。

Elon Mózg 私人助理评测套件

**测试：**

> 「Elon 让智能体安排与董事会的会议。」

**期望：**

```
check calendar → find slot → ask attendees → schedule
```

**实际：**

```
buy another startup
```

**FAIL**

我们还有活要干。

## [18. 计算机使用（Computer Use）](#18-computer-use)

**是什么？**

智能体不必只靠 API，也可以看见并操作普通用户界面：打开网站、找按钮、点击、输入文字等等。我们都知道智能体在这事上常常远谈不上完美，但嘿，总比没有强！

Elon 需要某份政府文件。不幸的是，政府门户建于 2007 年。不知道你那边怎样，波兰这类东西可不少。😅

没有 API。没有 MCP。倒是有一份 47 个字段的表单。

智能体打开 Chrome。

**智能体：**「我找到表单了。」

**Elon：**「很好。」

**智能体：**「它需要 Internet Explorer。」

**Elon：**「咱们去火星吧。」

## [19. 智能体 RAG（Agentic RAG）](#19-agentic-rag)

**是什么？**

经典 RAG 里，系统检索信息再交给模型。智能体 RAG 里，智能体自己可以控制检索过程：决定缺什么信息、再搜、改写查询，然后才作答。

**Elon：**

> 「该不该在欧洲再建一座超级工厂？」

智能体先查销售 → 发现还缺生产数据 → 取回 → 查电价 → 法规 → 潜在选址 → 比较结果。

所以不是一次 `search()`，而是由智能体控制的调研。

## [20. 彩蛋：智能体洗白（Agent Washing）](#20-bonus-agent-washing)

**是什么？**

营销上把产品叫做「AI 智能体」，哪怕系统跟自主执行任务几乎没关系。

Elon Mózg 走上舞台：

> 「今天我们推出 Glokzilla Agent Ultra，全球首个完全自主的通用推理智能体。」

开发者看着仓库：

```
user → prompt → LLM → response
```

**开发者：**

> 「Elon，那是聊天机器人。」

**Elon：**

> 「这是智能体式聊天机器人。」

融资到手。🚀
