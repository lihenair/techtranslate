# 你已经是一具肉身 Proxy

原文链接：<https://x.com/obie/status/2101779116056088732>

原文作者：Obie Fernandez

![文章头图](https://pbs.twimg.com/media/HSsEel2WwAESs-K.jpg:large)

作者：[Obie Fernandez](https://x.com/obie)（[@obie](https://x.com/obie)）

发布于 2026 年 9 月 20 日。

**同一套技术让我比以往都顺，也拆掉不少老朋友赖以过上体面日子的安排。我能劝他们用手头这截跑道，却没法保证每个人都会喜欢接下来发生的事。**

我很兴奋的那个未来，恐怕会让许多老朋友、以及几个我真心在乎的人很难熬。同一套技术让我比以往都顺，也正在拆掉他们赖以过上体面日子的安排。我可以劝他们用手头这截跑道。可以鼓励他们多主动一点。但我没法诚实地保证：每个人都会发现，自己喜欢生活里接下来发生的事。

## [「可我还想用自己的脑子啊！」](#but-i-want-to-use-my-brain-man)

昨晚跟一个老朋友喝酒。他是一家大而成功的创业公司的 staff engineer，公司里有几百号工程师。

朋友很绝望。按他自己的话说，他「已经不知道这活该怎么干了」。每次聊到这，我都会换着法子说：「那你怎么不问问 Claude，让它告诉你这活该怎么干？」

他的回答永远是同一句变体：「你不懂。」

昨晚我们绕来绕去，我终于烦了：「行了，让我看一眼终端。」

我们走到他的工作电脑前。他打开几十个浏览器标签、六七个终端，每个里面都跑着一份 Claude。我大概说了句：看起来你已经在用这东西干这活了嘛。

「对，但你不懂。我感觉什么都推不动。」他回。

「可我不明白你怎么会推不动。我新开一个 Claude，行吗？」然后我就开了。第一件事是切到 Fable——他在用 Opus——于是我给出的第一条实打实建议是：只要你在编排活，永远用 Fable，它比 Opus 聪明一个数量级。

「可我不想浪费 token 预算。」

我火了，训他：「不是浪费预算。Opus 烂。用。Fable。就这样。呃，你能用 Fable 吧？」

「嗯，应该可以。」

「那就什么都用 Fable。它聪明，不会坑你。」我说。

「可我还想用自己的脑子啊！」

这朋友不算笨。他也是那种会为生成式 AI 对人类做的事而绝望的朋友。

「去他的脑子。你跟我说了半年你不会干这活。Fable 比你聪明。比我聪明，比我们所有人都聪明，我没开玩笑。」

「那是机器！我拒绝相信它更聪明……」他抗议。

「哦，所以它是随机鹦鹉（stochastic parrot）？」我打断。

他皱眉：「我不是那个意思。我是说它没有灵魂。」

我们又吵了一阵。他要保持控制，我说那套东西你得放手。

他有点烦，但还是看着我演示：为结果写提示，而不是把活拆成细碎任务。我在主 monolith 目录里打了：

> This code is shit and the architecture is all fucked.

回车。朋友笑出来，不敢信。

「这就是你的 prompt？？？」

我说：「我对你们系统一无所知啊，总得从哪儿下手吧？」

我们一边笑，一边看 Fable 消化这条 prompt。这套系统上下文显然很多，它有的是材料。失败清单里全是缺测试覆盖、几千行的 God object、大把明显死代码——换句话说，一堆货真价实的技术债。

在我这种人眼里，这是一筐伸手就能摘的果子。

为了把话说死，我回车接受了 Fable 的第一条建议。几分钟后再回车，然后再回车，删掉一些死代码。我们开始提 PR。朋友求我一定设成 draft。行，随便。

Fable 继续干。朋友看 diff。就是删死代码和配套单测。我想接着推，朋友求我停。

「你不懂 Obie，我没法像你这样干。」

我逼他解释为什么。

他说他有老板、有队友，不能就这么改；他得先交计划，再按计划执行。

「很好，那就让 Claude 帮你写计划。」我回。

「我写过了！」

朋友点开 Confluence，给我看一堆一眼就是机器写的计划，讨论这套系统该怎么改架构、怎么打扫。

我靠，计划都有了！我当众纳闷他为什么不执行，问是不是老板没签字。

「不是，他根本不看这堆东西。」

什么鬼？

「我得跟团队一起干。他们会看。」

我有点不信，追着问：「你们团队必须看这些？」

我绝不信他的团队会把那些东西通读一遍。说白了，他们更可能让 Claude 替他们读。

他继续：「对啊，然后我还得把这些拆成 Jira 里的 epic 和 story。」

顺便说一句：读到这里的人，大概都懂公司里用 Jira 和 Confluence 意味着什么。一句话：他们*并不是把开发者产能放在第一位*。不过智能已经随手可取，这不再像从前那样是诅咒——至少我现在这么看。

「来，你的 Claude 已经通过 MCP 连上 Jira 了吧？」我转回终端，打下：

> we can't push this any of this work yet, let's put it into Jira as epics and stories first

Claude 立刻往 Jira 发了 5 个 epic，还表示马上要在下面建配套 ticket。

朋友慌了，按 ESC 叫停。

行。今晚的演示到此结束。

我追问他为什么不每天做一点增量改进。他的答案是：因为没人在思考。

这答非所问把我问懵了。

他接着抱怨，所有人都把思考交给 Claude，就像我刚才那样。他不想让脑子烂掉，不想整天坐着按回车。

啊。我好像开始懂了。

「那为什么一点进展都没有？」我问。

「我不知道，就像没人在想*任何事*了。」

这哥们拿着高薪，管理层（看起来）期望还低，却在抱怨*没法干活*？更糟的是，他为此抑郁，还焦虑自己的职业前景。按理说他至少比职级更低的同事更聪明、更能干活（不然当不上 staff engineer），可他现在是这副样子？我拿他当兄弟。我困惑，也担心。

我说：「你到底怎么了，把事做完就行，怎么做完不重要。随便什么都比天天空转强。」

他难道不知道结局是什么？对公司没有价值的高薪人，最后会变成没有薪水的人。

「可我不想只当一具肉身 Proxy（meat proxy）！」他抗议。

哈！

我这朋友早就是肉身 Proxy。这词还没流行时，他已经是了。我知道。他大概也知道，只是不肯认。我摇头。

「兄弟，你该整天按回车，然后去陪孩子玩，让 Claude 干活。Fable 他妈的聪明，你可以信它。」

他没听。他觉得我的立场有偏见。确实有，被成功带偏的那种。他指责我从不读自己产出的每一行代码。他说对了，而我为此自豪。

我主要做的是全新的、设计干净、测试齐全的 Ruby on Rails 内部系统。我不需要读 Claude 写出的每一行。最近几个月，我甚至不再用 Claude Code 盯着写代码，因为自主 agent 已经写了 75–80%。只有要加一块像样的新功能、或动大架构时，我才下场看细节。

朋友的处境显然不同。他碰的是生产系统里跟客户付款有关的那一块。所以我跟他说，那你就去读 Claude Code 改过的每一行。有何不可？

吵到后来很清楚：他不信任 Claude，是因为*他不想信任它*。总有一天，他得给这份恐惧起个准名字。他怕的是自己过时。

问题是，带着这种态度，他已经过时了。大概 80% 以上参与软件生产的人也是。职业生涯已经停在水面上，他们只是还没发觉。

## [怒火往上涌](#frustration-boiling-over)

巧的是，下面这条帖子昨天爆了，写这篇文章时已经超过 150 万浏览，互动铺天盖地。它显然戳到了行业的神经。

[嵌入内容（原站 Twitter）](https://x.com/i/status/2101526107128529120)

不用点走，帖子不长，我把预览后面再多抄一点，方便对照。

> ……所有东西都是 Claude Code 做的。我团队里没人喜欢这样。他们被逼着能发多少就发多少。高层说过好几次：推代码已经不是瓶颈，那我们为什么还慢？人们一天干 12 到 13 个小时，就是为了按回车。没人在读任何东西。公司里的人自己什么都不做。从 L1 到 L7，每个人都在干同一件事。跟 Claude 说话。没有胜利感。没人在修 bug。说白了，没人再思考了。所有事都是 LLM 做的。太吸走灵魂了。说真的，如果至少给我们时间把代码过一遍、看看什么走到了哪里，我倒不介意。但没有，目标就是发。不管发生什么。

这条帖子和它的情绪也戳到了我，但不是我猜大多数人被戳到的那个点。三十多年职业生涯里，我从来没真正当过肉身 Proxy。哪怕头五年，记忆里大多是冒名者综合征（impostor syndrome）、以及自己根本不知道在干什么——我几乎总是会质疑被吩咐的事，并试着先搞懂再动手。

大约 2000 年，我卷进 Extreme Programming 运动最早的那一波，工作上被提成技术负责人，后面的故事大家都知道。如果我处在接受上级方向的位置——我经常是——落地的方式通常*由我自己裁量*。这就是大家现在说的、值钱得要命的「品味和判断」。

大多数软件开发者没有这个。

大多数软件开发者甚至不去试，因为一直以来，当个稳定的团队球员就够了：跟流程走，不管那流程是什么，按薪水更高的人订好的计划交货。

大多数人不试，只是因为他们没有那根筋，或者因为把余力留给别的东西更轻松：家庭、游戏、旅行，随你点……只要老板高兴，支票够厚，日子就能过下去。

在我看来，也很显然：这套系统正在散架。余波不会好看。如果你领薪水只是为了嵌进一套流程——别人决定做什么，你把指令变成软件——恭喜，你是「肉身 Proxy」。如果你只是接更高层老板的方向，再转译成给别人的指令，你也是「肉身 Proxy」。

肉身 Proxy 还能有工作，只是因为惯性。现在的 AI 技术已经够替换所有肉身 Proxy；还没发生，只是因为这种量级的颠覆需要时间。

## [你到底想要什么？](#what-do-you-actually-want)

于是又回到我对朋友说的那句：「按回车，然后去陪孩子玩」，在给 Claude Code 写提示的间隙。

我是认真的。他不会奇迹般地变成我。我只想他每天做完一件有用的事，保住工作，还能剩点力气给两个漂亮的小女儿。后来公司大、也成功。我猜他还有一段跑道可以想清楚。很多人都有。组织惯性能让工资再发很久，哪怕这个岗位的经济理由已经开始蒸发。

所以把这段时间用上。看在老天的份上，享受一点。但要明白你在花什么。

因为我没法告诉你还剩多少时间。我只能告诉你：跟朋友争论一台基于计算机的智能有没有灵魂，看起来是对这段时间糟糕透顶的用法。

我不会给你那种安慰剂：去当架构师吧，AI 永远需要人做高层思考。架构是我二十多年来价值主张的一大块，但我完全预期 AI 会越吃越多。我预期它会吃掉几乎全部，直到留下的人只剩付钱建设和/或维护的那一侧。在组织架构图上往上挪一格，并没有把你挪出这套流程。

老朋友 @chadfowler 在写一本关于再生软件（regenerative software）的书：实现可以被替换，人们依赖的行为却能保住。走到那里，要挖出埋在现有软件里的知识，把义务写清楚，并建立一套办法来判断替换是否成立。今天，这仍然需要大量工程判断和经验；但我看不出任何理由，假定划边界、抽需求、设计校验会永远只属于人类。

这段历史转折最让我兴奋的，是这些能力一到手，我能多交出多少价值。回想 ThoughtWorks，再回想 Hashrocket，客户把我带进现场，*搞清楚该做什么*本身就是任务的一大块。我爱这份责任。现在也爱。给我更多能把决定付诸行动的能力，我立刻开始想：还能为付钱的人多做成什么。

这当然是偏好，不是铁饭碗证明。我抽屉里没有「AI 免疫证书」。我预期自己得天天继续演化自己做什么、怎么做，就像过去 30 年那样。

我说这话时很清楚：很多人觉得我这种跟工作的关系*累人*。他们只想要一份相对清楚的任务、一张不错的支票，以及工作之外的生活。我懂这种吸引力。可惜，我严重怀疑软件行业还会不会把这种安排，继续提供给每一个想要它的人。

那么，亲爱的读者，你到底想要什么？

如果想要的是厚支票、以及大量跟家人待在一起的空闲，就诚实面对。用 AI 工具把该尽的义务做到及格，再用腾出来的气口想下一步。你不欠这个行业一场终身恋爱。事实上，你也许该考虑彻底干点别的。

但如果你还能提起兴趣，想要*对「造什么」有更大发言权*，*现在就开始练这种判断*。能在工作里练就在工作里练。不行，就找一个业余时间也值得解的问题。去跟天天跟它过日子的人聊。用 AI 去调查、去顶你的假设、去推可以试什么。先定什么结果才配得上投入。然后把其中一个想法推到足够远，看看自己当初对不对。认真说，没有比现在更好的时机。

我给朋友做的那个小演示，二十分钟里产出了一份 draft PR 和几个 Jira epic。我们从没走到能确认任何重要的东西变好了。睡一觉、写这篇的过程中，我想明白一件事：把「这到底重不重要」追问到底，恰恰是我希望朋友别再后退的那份工作。如果障碍是要五个人同意做某件事，那让他们同意就是工作的一部分。Claude 能帮你准备，但你还是得去跟需要合作的人交手，对吧？

写给这位我会把文章发给他的朋友：*这周就挑一件事*。小到能做完，大到会有另一个人注意到。能让机器干的，尽量让它干。看接下来发生什么。结果错了，查出原因，继续。*你不会因为亲自多敲了几行代码，就更不像肉身 Proxy。*

我不能保证这能保住你的软件工程师生涯。但它给了你一个机会：趁你还有时间做实验，去看看这些以前没有的能力，你能拿来做成什么。

至于那些读到这里一直在说「不、不、不！」的人，我只有一句。站在这波 AI 潮前面发脾气，挡不住你被卷走。

你真的还想用自己的脑子？不想让它烂掉？先搞清楚你到底想要什么，然后让 Claude 去干。
